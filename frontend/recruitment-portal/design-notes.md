# Design Notes — RecruitHub HR 后台原型

## 1. 交付概览

- 任务: 招聘系统首版 HR/招聘者后台前端页面设计（核心 5 页）。
- PRD/Spec: `docs/recruitment-system/spec.md`（workspace 根，亦在仓库 `docs/recruitment-system/spec.md`）。
- 原型入口: `index.html`，纯静态 HTML + CSS + 原生 JS（hash 路由），无外部构建依赖，可直接双击打开或用任意静态服务器访问。
- 推荐视窗: 1440×900（最小支持 1280×800，Kanban 区内部可横向滚动）。

## 2. 基线与参考

- 仓库: `repos/fanym22/Delivery-AI-Test` @ `feat/b5724dc8-jdhl`（当前为 Python 记账 CLI，无前端代码，原型为新建静态前端）。
- 设计系统: `knowledge/design-system/` 为空，因此采用企业 SaaS 通用"专业商务蓝"视觉语言：
  - 主色 `#1F5FEB`，辅助 `#0F3B99`/`#E8EFFE`；
  - 成功/警告/错误/信息色：`#16A34A`/`#F59E0B`/`#DC2626`/`#0EA5E9`；
  - 中性色、间距（4px 网格）、圆角（6/8/12）与组件形态参考 Ant Design / Linear 类企业 SaaS。
- 目录结构:
  ```
  prototype/
    index.html
    assets/styles.css
    assets/app.js
    design-notes.md
  ```

## 3. 页面与路由（hash 路由）

| 页面 | Hash | 说明 |
|---|---|---|
| 登录页 | `#/login` | 未登录自动重定向；任意合法账号密码可登录；输入密码 `wrong` 可查看错误态 |
| 职位列表 | `#/jobs`（默认） | 搜索 + 部门/状态筛选；表格行点击进入看板；行内编辑/上下架/关闭操作 |
| 新建职位 | `#/jobs/new` | 表单分组：基础信息 / JD；支持"保存草稿"和"发布" |
| 编辑职位 | `#/jobs/:id/edit` | 回填现有数据；未保存离开拦截 |
| 候选人看板 | `#/jobs/:id/board` | Kanban 7 列（简历筛选→已入职），拖拽推进阶段，点击卡片打开右侧抽屉 |
| 候选人详情 | `#/candidates/:id` | 基本信息/教育/工作/时间线；支持推进/回退阶段、淘汰（含原因）、添加备注 |

非首版模块（候选人库、数据报表、系统设置）在导航中置灰并提示"首版暂未开放"。

## 5. Mock 数据说明

- 内置 7 个职位、10 名候选人，覆盖各阶段样本；所有状态变更仅保存在内存，刷新页面会重置。
- 登录态保存在 `sessionStorage.recruit_authed`。
- 可用于演示的关键路径:
  1. 登录 → 职位列表 → 新建职位并发布 → 返回列表看到新职位。
  2. 点击"高级前端工程师" → Kanban 看板 → 拖拽卡片到下一列 → 查看推进确认。
  3. 点击卡片 → 抽屉"查看完整详情" → 候选人详情 → 添加备注/推进/淘汰。

## 6. 限制与待确认

- 响应式: 按需求仅针对桌面端（≥1280px），不做移动端断点。
- 后端/API: 本原型为静态前端，不发起任何网络请求；真实接口、权限模型、简历解析、邮件/日历对接等已在 PRD 的 `Open Questions` 中登记，待后续节点确认。
- 设计系统: 当前主题色、字体、组件 token 为原型内手工定义；接入真实 design system 时以 CSS 变量替换即可。
- 拖拽: 使用原生 HTML5 DnD，移动端/无障碍拖拽体验未优化（首版桌面端可接受）。

## 7. 已知小瑕疵（非阻塞，后续迭代优化）

- 职位/姓名头像缩写使用字符末 2 位，中文场景下视觉上略简，可替换为姓名首字或图标。
- 看板拖拽目前只支持鼠标事件，键盘拖拽未实现。
- 表单"未保存离开"拦截使用自定义弹窗（不使用浏览器 beforeunload），因为这是 SPA hash 路由。
